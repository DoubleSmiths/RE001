# 0021. 전투 능력의 조작 영역과 준비 상태

- 상태: 채택
- 날짜: 2026-09-10

## 맥락
첫 포획에 수동 능력을 추가한 뒤 실제 게임뷰를 확인하니 버튼이 귀환/여정과 하단 탭 사이에 묻혀 있었다. 6개일 때는 귀환/여정과 세로 영역이 겹쳤다. 또한 스프라이트를 지정하지 않은 UGUI Filled Image는 fillAmount를 무시하므로, 재사용 시간이 0이어도 검은 마스크가 아이콘 전체를 계속 덮었다. 전투 전용 버튼이 마을에도 남았다.

## 결정
기존 6칸 규칙과 능력 발동 경로는 유지한다. 전투 기록 아래, 전리품 위의 독립된 행에 버튼을 놓고 기존 PreLoad 프레임 `11_orange_button_xs_empty`를 재사용한다. 이 스프라이트는 중앙도 불투명하므로 아이콘 뒤에 배치한다. 마지막으로 선택한 능력의 이름과 사용 가능/재사용 대기/체력 가득/대상 대기 상태를 한·영으로 표시한다.

재사용 마스크는 위쪽에 고정된 사각형의 실제 높이를 남은 비율에 맞춰 줄이고, 준비되면 비활성화한다. 초 숫자는 슬롯의 독립 자식으로 중앙을 유지한다. 능력이 없거나 전투 밖이면 CanvasGroup의 표시와 입력을 함께 끈다. 팝업이 열려 있는 동안에도 능력바 입력은 차단한다.

## 결과
`_tools/upgrade_combat_hud.py --apply`와 Unity 로컬 파싱으로 상태 번역을 재생성한다. 위치·크기·리소스·문구 키는 Define에 둔다. `_tools/verify_skillbar.cs`는 저장을 차단한 UI 검증 세션에서만 실행한다. 6개 슬롯의 화면 범위·다른 조작부와 겹침·최상위 레이캐스트, 실제 발동 후 마스크/숫자, 전투 상태 전환, 팝업 입력 차단, 언어 전환을 검사한다. 새 Graphic의 렌더 깊이가 확정된 다음 프레임에서 레이캐스트를 측정한다.

이 검증은 Editor 게임뷰 범위다. Android 기기의 터치 크기·화면비·성능 검증을 대신하지 않는다.
