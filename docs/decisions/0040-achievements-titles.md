# 0040. 업적·칭호 — 분야마다 단계 사다리, 칭호는 HUD 이름 자리에

- 상태: 채택
- 날짜: 2026-09-30

## 맥락

두 레퍼런스 모두 평생 기록 보상(업적)이 있고, 방치형 RPG 에서는 칭호로 보여 주는 것이 흔하다. 우리 게임엔 일일·주간·가이드만 있었다.
`MissionManager` 는 이미 이벤트별 누적 기록(`MissionSaveData.Lifetime`)을 모으고 있었다(가이드 판정용).
사용자 결정(2026-09-30): 빠진 재미 요소 네 가지 모두 넣기(ADR0039 과 같은 결정).

## 결정

- **표는 미션 표 Kind `Achieve`**(`_tools/gen_missions.py`, 45행) — 12분야(처치·보스·돌파·레벨·도감·포획 시도·패링·훈련·강화·요일 던전·
  배달 의뢰·일일 완료)마다 3~5단계. 판정은 가이드와 같다(레벨·도감·돌파 수는 상태, 나머지는 누적 기록).
- **분야마다 사다리**: 받지 않은 첫 단계만 보이고 받으면 다음 단계가 열린다(`CurrentAchieve`). '모두 받기'는 사다리를 끝까지 탄다.
- **보상**: 단계마다 크리스탈(합계 4,180), 17개 단계엔 칭호(`HonorKey` — 사냥꾼·마물 학살자·전설의 사냥꾼·보스 사냥꾼·개척자·대륙 정복자·
  만렙 여행자·마물 학자·살아있는 도감·조련사·패링 달인·철벽·수련광·대장간 단골·던전 탐험가·마을의 해결사·성실한 여행자). 영어 칭호는 HUD 폭 때문에
  10자 이하.
- **칭호는 얻은 단계에서 나오고(따로 저장하지 않는다) 하나를 단다**(`MissionSaveData.Honor`). 첫 칭호는 얻는 순간 자동으로 단다.
  업적 탭 맨 위 줄을 누르면 없음 → 첫 칭호 → … → 없음 순으로 바뀐다(`claim:false` 라 '모두 받기'가 누르지 않는다).
- **HUD 이름 자리(PlayerRankText)에 금색 칭호** — 달지 않았으면 이름. `UI_GameScene` 이 `Mission.OnChanged` 를 구독해 바로 바뀐다.
- 칭호에 능력치는 붙이지 않는다(보여 주기만) — 밸런스를 흔들지 않고, 크리스탈 보상이 이미 있다.
- '모두 받기'로 칭호를 여럿 얻으면 알림은 끝에 한 번('칭호 획득! [사냥꾼] 외 4개', `BeginClaimBatch`/`EndClaimBatch`).
- 미션 창 열째 탭 '업적'(탭 줄 5×2 가 가득 찬다). 큰 수는 자릿점(100,000) — 모든 미션 제목에 적용.

## 결과

- 실측(개발 세이브 + 누적 처치 25,000·패링 150): 모두 받기 → 크리스탈 +830, 칭호 5종(사냥꾼 자동 장착 → HUD 금색), 바꾸기 순환, 알림 한 번.
- 기존 세이브의 누적 기록은 미션 시스템(v2 P1) 이후만 있다 — 그 전의 처치 수는 세지 않는다.
- 새 분야를 더할 때는 `Define.MissionEvent` 와 `Notify` 호출만 있으면 표에 행을 더하는 것으로 끝난다.
