# 0006. 방치 보상(오프라인 수익) 설계

- 상태: 채택
- 날짜: 2026-08-14

## 맥락

목표가 "완성된 방치형 게임"인데, 방치형의 두 축 중 하나가 비어 있었다.

- 자동 전투: **있음** — `PlayerController.AutoAttack` + `UI_BattleBtnGroup.CoBattleLoop`이
  몬스터를 계속 스폰하고 플레이어가 자동으로 싸운다.
- 오프라인 보상: **없음** — 코드 전체에 경과 시간을 다루는 곳이 없었다(`TimeManager`도 주석 처리 상태).

껐다 켜면 그동안의 진행이 0이라 "방치"할 이유가 없는 상태였다.

## 결정

`GameManager.ClaimOfflineReward()`로 정산한다. 게임 시작 시(데이터·플레이어 준비 후) 1회 호출.

| 항목 | 값 | 이유 |
|---|---|---|
| 상한 | 8시간 | 하루 종일 켜둬야 이득인 구조를 피한다 |
| 효율 | 실제 사냥의 50% | 직접 플레이할 이유를 남긴다 |
| 처치 간격 | 4초/마리 | 실제 전투(스폰 2s + 접근·교전)에 맞춤 |
| 최소 시간 | 1분 | 씬 전환·잠깐 이탈에 정산이 뜨지 않게 |

보상은 **마지막으로 머문 전투 지역**의 몬스터 평균으로 계산한다(`LastBattleAreaId`).
지역을 모르면(전투 경험 없음) 지급하지 않는다.

기준 시각(`LastSeenTicks`)은 `Managers.OnApplicationPause` / `OnApplicationQuit`에서 기록한다.
모바일은 종료 대신 일시정지로 빠지는 경우가 많아 둘 다 건다.
`0`이면 최초 실행으로 보고 지급하지 않는다 — 안 그러면 1970년부터의 보상이 쏟아진다.

## 보강: 켜둔 채 전투 밖에 있을 때도 누적한다 (2026-08-14 추가)

전투 구역을 벗어나면 `CoBattleLoop`이 멈춰 **진행이 완전히 정지**했다.
마을에서 장비를 보거나 대화하는 동안 아무것도 쌓이지 않는다면 방치형이라 할 수 없다.

`GameManager.TickIdle(deltaTime)`을 `Managers.Update`에서 매 프레임 돌린다.

- 전투 구역 **밖**에서만 누적한다. 전투 중에는 실제 전투가 100% 효율로 보상하므로
  누적을 끈다 — 안 그러면 이중 지급이 된다.
- 효율·간격은 오프라인 정산과 같은 상수를 쓴다. 같은 사냥을 자리 비운 방식만 다르게 하는 것이므로
  두 경로의 수익이 달라지면 안 된다.
- `Time.unscaledDeltaTime`을 쓴다. 팝업으로 `timeScale`이 0이 되어도 방치는 멈추면 안 된다.

## 보강: 진행을 화면에 알린다 (2026-08-14 추가)

방치로 골드·EXP가 오르는 것 자체는 HUD에 이미 실시간 반영된다
(`Gold` setter → `OnResourceChanged`, `GainExp` → `OnExpChanged`).
문제는 **왜 오르는지 알 수 없다**는 것이었다.

`GameManager.OnIdleBatch` 이벤트로 **60초마다 묶어서** 알린다.
매 처치마다 띄우면 스팸이 되고, 알림이 없으면 숫자만 혼자 움직인다.
안내에는 지역 이름을 넣어 "어디서 사냥 중인지"를 드러낸다.

  > 방치 사냥 중 — 신들바람 숲 입구에서 7마리
  > 경험치 315 · 골드 147

## 결과

- 새 전투 지역을 추가하면 `UI_GameScene.SwapAreaBtnGroup`이 자동으로 `MarkBattleArea`를 남긴다.
  (2026-09-29 수정: 처음엔 `EnterArea`에만 걸었는데 전투 진입은 전부 `EnterAreaWithFade` 경로라
  `LastBattleAreaId`가 0으로 남아 실제 플레이에서는 오프라인 보상·방치 누적이 한 번도 돌지 않았다.
  두 경로가 모두 지나는 `SwapAreaBtnGroup`으로 옮겼다. 위 검증은 지역 값을 직접 넣고 한 것이었다.)
- 같은 날 리뷰 반영(보상이 실제로 나가기 시작하면서 드러난 구멍):
  - 평균은 **출현 가중**이다(`GameManager.TryGetAreaAverage` ← `ObjectManager.FieldPool`). 단순 평균은 희귀·우두머리가 끼인
    27개 노드에서 기대값의 최대 2.1배를 줘 "직접 사냥보다 낮게"를 넘었다. `_tools/sim_economy.py`는 원래 가중 평균이었다.
  - 앱 복귀(`OnApplicationPause(false)`)에서도 정산한다. 프로세스가 살아 있으면 GameScene 이 다시 로드되지 않아 홈에 나갔다 온
    시간이 통째로 사라졌다. 방치 누적(`TickIdle`)은 한 프레임에 1초까지만 센다 — 복귀 첫 프레임의 `unscaledDeltaTime`엔
    백그라운드 시간 전체가 들어와 상한 없이 한꺼번에 지급될 수 있었다.
  - 정산을 마친 뒤부터는 저장할 때마다 `LastSeenTicks`를 갱신한다. 전에는 일시정지·종료 때만 기록해서 비정상 종료 뒤
    다음 실행이 이미 플레이한 세션 시간을 또 지급했다.
- 몬스터 경험치·골드를 조정하면 방치 수익도 같이 변한다([[0003]]의 상대값 설계와 연동).
- 안내는 전용 팝업 없이 토스트를 재사용한다. 연출 스펙이 정해지면 그때 전용 프리팹으로.
- 검증(플레이 모드 실측): 3시간 → 1,350처치 / EXP 100,170 / 골드 28,822.
  20시간 → 8시간분만 정산(상한 동작). 30초 → 미정산.
