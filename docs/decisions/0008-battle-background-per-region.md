# 0008. 전투 배경은 지역별 색조로 구분한다 + 배경 소유권 규칙

- 상태: 채택
- 날짜: 2026-08-14

## 맥락

전투 배경 프리팹은 `CH1BG` 하나뿐이고 `UI_BattleBtnGroup.ChangeMap()`에서 하드코딩으로 띄운다.
심층 30개를 도는데 배경이 하나면 진행감이 없다.

여기에 더해 **재진입 시 배경이 사라지는 버그**가 있었다.
시연 영상에서 동굴·성소 구간이 검게 나온 원인이 이것이었다(아트 누락이 아니었다).

원인은 파괴 순서다. 전투 → 전투로 지역을 옮기면
1. 새 `UI_BattleBtnGroup.Init()` → `ChangeMap()`이 배경을 만들고
2. **그 뒤에** 이전 그룹의 `OnDestroy` → `EndBattle()`이 발화하는데,
3. 이때 이름(`CH1BG`)으로 싹 지워서 **방금 만든 새 배경까지 지웠다.**

같은 패턴이 마을 배경에는 이미 수정돼 있었고(코드 주석에 기록됨) 전투 배경에만 남아 있었다.

## 결정

**색조로 구분한다.** 지역별 배경 아트를 새로 만들려면 무한 스크롤용 **이음매 없는**
패럴랙스 레이어 5장이 필요한데, AI 생성으로는 이음매를 보장할 수 없다.

- 숲: 원본 / 동굴: 서늘한 푸른빛 / 성소: 스산한 보랏빛
- 뒤쪽 레이어일수록 색조를 진하게(0.45→1.0 보간) — 깊이감을 주고 앞쪽은 살려
  캐릭터 대비를 유지한다
- 몬스터 심층 색조([[0003]])와 같은 아트 디렉션이라 톤이 어긋나지 않는다

**배경 소유권**: `UI_BattleBtnGroup`이 자기가 만든 인스턴스를 `_battleBG`로 들고,
`EndBattle`은 **그 참조만** 파괴한다. 이름으로 훑지 않는다.
stray 정리는 새 그룹의 `ChangeMap()`이 담당한다.

## 결과

- 새 지역을 추가하면 `REGION_TINTS`에 항목을 넣는다. 없으면 원본(숲) 색으로 나온다.
- 씬에 배치되는 배경을 늘릴 때 **이름 기반 일괄 파괴를 쓰지 않는다.**
  Unity의 `Destroy`는 프레임 끝까지 지연되므로, 생성-파괴 순서가 엇갈리면 새 것이 죽는다.
- 진짜 지역별 배경 아트가 생기면 이 결정을 대체한다. 그때는 `TravelNode.Sprite`를
  배경 프리팹 키로 쓰는 방향이 자연스럽다.
