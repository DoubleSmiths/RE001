# 0046. 비공개 테스트용 기기 안 플레이 기록 · 설문지

- 상태: 채택
- 날짜: 2026-09-30

## 맥락

사용자 질문(2026-09-30): "게임의 재미 검증은 끝났나?" — 아니다. 자동 봇(전 구간 플레이스루)과 개발자 확인뿐이라 막히지 않는다는 것만
안다. 사람이 해 봐야 한다. 구글 플레이 개인 계정은 어차피 정식 출시 전 비공개 테스트(12명 × 14일)가 필수다.
재미·속도를 판단하려면 테스터가 **어디까지 얼마나 걸려 갔고 어디서 막혔는지**가 필요한데, 분석 SDK(Firebase 등)를 넣으면
스토어 데이터 보안 답이 "수집 있음"으로 바뀌고 서버·계정이 필요하다.

## 결정

- **기기 안 기록만** — `Utils/PlaytestLog.cs` 가 `persistentDataPath/playtest_log.txt` 에 한 줄씩(시각 · 누적 플레이 초 · 사건 · 내용).
  사건: 세션 시작·멈춤·재개·끝(`Managers.OnApplicationPause/Quit`, `GameScene.BindPlayer`), 레벨, 스테이지 첫 돌파·보스 실패,
  쓰러짐, 퀘스트 완료, 광고·유물 소환·구매(모의), AUTO 해금. 512KB 를 넘으면 앞 절반을 버린다. 누적 플레이 시간은 PlayerPrefs
  `PLAYTEST_SECONDS`. 기록 실패는 경고만 — 게임을 멈추지 않는다. 기기 밖으로 보내지 않으니 데이터 보안 답은 그대로다.
- **테스터가 보낸다** — 설정 '시스템' 줄에 [플레이 기록](빌더 `ReleaseSetup.ExtendSettingPopup` — [크레딧][플레이 기록][게임 종료]).
  누르면 요약(총 시간·세션·Lv5~300 도달 시각·돌파/보스 실패/쓰러짐·가장 막힌 곳·광고/소환/구매·최근 15줄)을 크레딧 창
  (`UI_CreditsPopup.ShowText`)으로 보여 주고 클립보드에 복사한다 — 설문지 마지막 칸에 붙여 넣는다.
- **설문지·판단 기준** — `Documents/Playtest/Closed_Test_Survey.md`(1일째·7일째, 재미 B1~B8 · 속도 C · 상점/광고 D · 헷갈림 E,
  목표 가설: 첫 10분 4.0/5, 내일 또 60%, 속도 '적당' 50%, Lv20 첫 1시간 안).

## 결과

- 실측(에디터): 보스 실패 2회 → 돌파 → 광고 → 10회 소환 → 레벨업 후 [플레이 기록] → 요약에 "스테이지 1곳 돌파(마지막 1-1) ·
  보스 실패 2회", "가장 막힌 곳: 1-1 ×2", "광고 1회 · 유물 소환 1회", 레벨 도달 시각, 최근 15줄 — 클립보드와 같다.
  켜자마자 오는 '재개'를 세션으로 세던 것을 고쳤다(게임 씬에 들어온 뒤의 재개만).
- 테스트가 끝나면 요약 줄을 모아 레벨 곡선·보스 수치·광고 보상을 조정한다. 분석 SDK 는 정식 출시 뒤 필요할 때 따로 결정한다.
