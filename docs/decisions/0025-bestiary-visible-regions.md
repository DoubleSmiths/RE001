# 0025. 도감 목록은 보이는 지역의 칸만 생성

- 상태: 채택
- 날짜: 2026-09-10

## 맥락

25개 지역의 503종을 매번 생성하면서 Editor에서 도감 첫 프레임까지 약 0.69초가 걸렸다. 미사용 Tween 2,012개를 제거한 뒤에도 프레임 할당 약 53MB와 칸 생성 비용이 남았다. 기존 지역별 연속 스크롤을 유지하며 비용을 줄여야 한다.

## 결정

지역 헤더와 전체 목록 높이는 유지하고, 화면 근처 지역만 몬스터 칸을 생성한다. 높이는 프리팹의 실제 셀 크기·간격·패딩·가용 폭으로 계산한다. 멀어진 지역의 칸은 해제하고 돌아올 때 현재 MinMon 데이터를 다시 적용한다.

지역 단위는 한 번에 약 20종이므로 기존 프리팹과 클릭·별 연출을 재사용할 수 있다. 페이지 선택 UI 추가나 503칸 상시 보관은 하지 않는다.

## 결과

도감 전체 데이터를 판단할 때 인스턴스화된 `UI_BestiaryBox` 수를 사용하면 안 된다. Creature/MinMon 데이터가 원천이며 화면의 칸은 일부다. 동행·등급 연출은 화면에 존재하는 칸에 적용하고, 다시 생성하는 칸은 최신 상태를 읽는다.

검증은 변경 전의 전체 높이 5,133과 503종 배치를 기준으로 양방향 탐색·최대 동시 칸 수·재생성 후 클릭·종료 정리를 확인한다. Android 성능은 별도로 측정해야 한다.
