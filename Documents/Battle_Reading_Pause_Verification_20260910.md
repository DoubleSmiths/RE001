# 도감·포획 중 전투 정지 검증

## 문제와 변경

정상 속도 새 게임 관통에서 첫 도감을 읽다가 배경 전투로 사망했다. 전투 중 도감, 마물 상세, 포획, 나의 미니몬 창이 스택에 있으면 월드 시간을 정지한다. 하위 상세 창을 추가하거나 닫아도 정지가 유지된다. 마을의 도감은 시간을 멈추지 않는다.

공격을 취소하지 않고 남은 타격 시간을 보존한다. 콤보와 능력/물약 재사용 시간, 자동 물약과 수동 전투 능력도 정지 상태를 따른다. 팝업·알림의 저작 Tween과 Animator, 대화 화살표와 닫기 대기는 실제 시간으로 진행한다. 마지막 정지 사유가 사라지면 기존 배율을 정확히 복원한다. SoulShop과 씬 Clear도 같은 상태 관리에 포함한다.

포획에서 특정 입장 모션을 끄는 DOTweenAnimation.DOKill이 같은 오브젝트의 유혹·성공 모션까지 죽이는 문제를 추가 발견했다. 교체할 Tween만 종료하고, ID로 선택한 저작 Tween만 생성·재생한다.

결정: [ADR0026](../docs/decisions/0026-battle-reading-pause.md).

## 환경과 방법

Unity 6000.3.10f1, Windows Editor Play Mode. 코드 수정 후 `editor refresh --compile` 및 오류 콘솔 확인. `_tools/unity_exec.py`로 아래 C# 검증을 실행한다. 비동기 도구 반환은 완료가 아니므로 최종 PASS 로그를 확인한다.

- `verify_battle_modal_pause.cs`: 실제 플레이어 Animator와 공격 코루틴, 실제 TakeHit을 사용한다. 격리된 대상 몬스터의 Update/물리는 꺼져 있다. PlayerController와 AbilityRunner Update는 실행한다. 30초 실제 시간 동안 타격 직전 상태를 확인한다.
- `verify_battle_pause_clear.cs`: 0, 0.25, 1, 10배의 복원, SoulShop 중첩 상태의 Clear, 다음 정지 주기의 복원값, 전역 DOTween 배율 보존을 검사한다.
- `verify_paused_capture.cs`: 실제 UI 레이캐스트와 포획 연출을 통과한다. 유혹 성공/실패 결과만 디버그 훅으로 고정한다. GameData와 저장 경로를 격리하고 종료 때 복원한다.

## 결과

수정 전 전투 중 도감을 열어도 0.5배가 그대로 유지되는 실패를 확인했다. 수정 후 공격 정지 검사는 **29개 통과**했다.

| 측정 | 결과 |
|---|---|
| 실제 대기 / 게임 시간 경과 | 30.004초 / 0.000000초 |
| 공격 Animator normalizedTime | 0.298572 → 0.298572 |
| 대기 중 타격 | 0회 |
| 콤보 잔여 시간 | 9.696452 → 9.696452 |
| 플레이어·물약 UI의 회복/신속 쿨타임 | 59.392900 → 59.392900 |
| 공유 능력·주기 능력 잔여 시간 | 59.696460 → 59.696460 |

중첩 상세 창, 마을 도감, SoulShop을 먼저/나중에 여는 순서 모두 통과했다. Clear 뒤 스택·전투 정지·SoulShop·SceneUI가 초기화되고 배율 1로 돌아왔다. 그다음 0.25배 주기도 이전 복원값에 오염되지 않았다.

유혹 성공·실패에서 입장 이동 176, 버튼 등장 간격 약 0.50초, 유혹 이동 약 6, 성공 이동 약 5와 제자리 복귀를 확인했다. 이모지 Animator와 공명도 숫자가 정지 중에도 진행된다. 결과 연출 중 닫기는 차단되고 완료 후 닫힌다. 시도 횟수·포획 수·관심 소비와 원본 데이터 복원 검사도 통과했다. 수정 전 유혹 이동이 없고 성공 Tween 진행값이 0이던 실패를 재현했다.

검증기에서 실제 프리팹에 없는 버튼 크기 애니메이션을 기대한 것과, raycastTarget=false인 X 이미지 자체를 입력 수신자로 기대한 것은 검증기 오류였다. 실제 순차 등장과 X 위치의 배경 버튼 수신을 검사하도록 정정했다.

만드라고라 확정 포획을 포함한 최종 3경로도 PASS다. 만드라고라 1개만 소비되고 포획 수와 결과 창이 정상 반영됐다. 이 경로에서도 성공 이동 약 5, 제자리 복귀, 하트 Animator 진행값 2.38을 확인했다. 최종 실행의 오류·경고 수집과 Unity 오류/경고 콘솔은 모두 0건이다. 별도 읽기 전용 코드 리뷰에서 중요한 결함은 발견되지 않았다.

검증 종료 후 Unity를 정상 종료하고 원래 SaveData와 PlayerPrefs 백업을 복원했다. 재실행 전후 SaveData SHA256은 `CB727D514D88ABBAC1635E9A15EB67215376606120A11C2B4BB066182EE1FC38`로 일치한다. 복구창 없이 TitleScene 에디터로 진입했으며 재컴파일 후 오류 콘솔 0건이다. 에디터 시작 시 기존 Input Manager 사용 중단 예정 안내 1건은 별개로 남아 있다.

## 한계

위 공격 검사는 적 AI가 실제로 계속 공격하는 장시간 전투나 Android 실기기 검증을 대체하지 않는다. 포획 결과를 고정했으므로 확률·정상 플레이 경제 검증도 아니다. 실제 기기 터치, 백그라운드 복귀, 외부 플레이어의 재미 평가는 별도 미검증이다.
