# 도감 Tween 생성 비용 검증

## 변경과 원인

`UI_BestiaryBox`의 저작 Tween 4개는 재생 호출이 없는데도 Awake에서 생성되어, 503칸을 열 때 대기 Tween 2,012개가 추가됐다. 프리팹의 `autoGenerate`만 껐다. 실제 클릭·별 등급·동행 연출은 코드 경로를 유지한다.

기존 용량 설정은 `Managers.Init()`의 조기 반환 뒤에 있어 씬의 Managers가 먼저 Awake되면 실행되지 않았다. 기존 용량 7,812/625를 `BeforeSceneLoad`에서 설정하고 Define 상수로 옮겼다.

## 실측

Unity 6000.3.10f1 Editor, 같은 레벨 15 마을 저장, 정상 속도. `_tools/verify_bestiary_tween_cost.cs`로 3회 생성·닫기를 반복했다.

| 측정 | 변경 전 | 변경 후 |
|---|---:|---:|
| 생성된 도감 칸 | 503 | 503 |
| 미사용 저작 Tween | 2,012 | 0 |
| 열린 동안 활성 Tween | 약 2,123 | 104~111 |
| 닫기 후 활성 Tween | 81 | 81 |
| 동기 생성 시간 | 422~440ms | 418~442ms |
| 첫 UI 프레임까지 | 801~843ms | 689~729ms |
| 해당 Editor 프레임 GC 할당 최고값 | 54.8~59.1MB | 52.8~57.0MB |

GC 값은 `ProfilerRecorder`의 전체 Editor 프레임 값이며 도감만의 할당량이 아니다. `GetAllocatedBytesForCurrentThread()`는 이 환경에서 0을 반환하므로 근거로 사용하지 않는다. 시간은 3회 범위이며 실기기 성능을 의미하지 않는다.

발견/미발견 클릭 차단, 클릭 Punch, 별 1~3단계 색·회전·숨김, 동행 분홍 프레임, 무관한 Tween 보존 검사를 통과했다. 시작 용량은 7,812/625, 검사 구간 오류/경고는 0건이다. 처음 추가한 별 검사에서 Unity `Color.yellow`를 순수 FFFF00으로 잘못 가정한 검증 코드 오류는 기대 색을 명시한 뒤 재실행했다.

컴파일 후 오류 콘솔 0건을 확인하고 Play에서 실행했다. 읽기 전용 코드 리뷰에서 생산 변경 결함은 발견되지 않았고, 검증 도구에 발견·미발견·동행 전제를 명시했다.

## 남은 비용

503칸을 매번 동기 생성하는 구조와 큰 프레임 할당은 남아 있다. 이번 변경만으로 도감 지연이나 모바일 성능 문제가 해결됐다고 판단하지 않는다. 다음 작업은 화면에 필요한 목록만 생성하면서 전체 탐색·스크롤·상태 갱신을 보존하는 것이다.

로컬 원본 로그: `Verification-20260909-Gameplay/commercial-20260910/editor-bestiary-gc-red.log`, `editor-bestiary-green.log`.

## 후속: 화면 근처 지역만 생성

지역 헤더 25개와 기존 전체 높이 5,133을 유지하면서 viewport와 한 행 여유 범위 안에 있는 지역의 칸만 생성한다. 화면 밖 칸은 Tween 정리 후 숨기고 해제한다. 지역을 다시 방문하면 현재 기록도·별·동행 상태로 새 칸을 만든다. 정책은 ADR0025에 기록했다.

`_tools/verify_bestiary_layout.cs`로 변경 전 기하 구조를 저장했고, 기준 파일은 `_tools/fixtures/bestiary-layout-20260910.json`이다. Creature 데이터나 도감 프리팹을 의도적으로 바꾸면 이 기준도 새 배치를 검토한 뒤 갱신해야 한다.

`_tools/verify_bestiary_visible_regions.cs`의 동일 저장·3회 측정:

| 측정 | 전체 칸 생성 | 가시 지역 생성 |
|---|---:|---:|
| 첫 화면 칸 | 503 | 20 |
| 왕복 중 최대 동시 칸 | 503 | 43 |
| 동기 생성 | 421~429ms | 69~104ms |
| 첫 UI 프레임까지 | 687~688ms | 95~153ms |
| 해당 Editor 프레임 GC 할당 최고값 | 52.8~53.3MB | 6.0~6.3MB |

변경 전 동시 칸 제한 54건 실패 → 변경 후 실패 0건. 503종 전체를 순서대로 탐색하고 역순으로 돌아오면서 모든 지역 높이·칸 좌표·전체 스크롤 높이가 기준과 같음을 확인했다. 재생성 후 실제 상세 클릭, 화면 밖 동행 해제 후 돌아오기, 화면 안 동행 설정, 25개 지역명 한영 전환, 같은 프레임 SetInfo 2회, 즉시 닫기와 반복 종료도 통과했다.

기존 Tween/별/클릭 검증도 가시 칸 기준으로 재실행해 통과했다. 이때 20칸·저작 컴포넌트 80개 중 미사용 Tween 0, 닫기 전후 81개 유지, 오류/경고 0건이었다. 컴파일·오류 콘솔 0건과 실제 게임뷰 첫 화면도 확인했다.

이번 실측은 Editor이며, 실제 터치 드래그 프레임·다른 화면비·Android 메모리는 아직 미검증이다. 원본 로그: `editor-bestiary-visible-red.log`, `editor-bestiary-visible-green.log`.
