# 도감 Tween 생성 비용 검증

## 변경과 원인

`UI_BestiaryBox`의 저작 Tween 4개는 재생 호출이 없는데도 Awake에서 생성되어, 503칸을 열 때 대기 Tween 2,012개가 추가됐다. 프리팹의 `autoGenerate`만 껐다. 실제 클릭·별 등급·동행 연출은 코드 경로를 유지한다.

기존 용량 설정은 `Managers.Init()`의 조기 반환 뒤에 있어 씬의 Managers가 먼저 Awake되면 실행되지 않았다. 기존 용량 7,812/625를 `BeforeSceneLoad`에서 설정하고 Define 상수로 옮겼다.

## 실측

Unity 6000.3.10f1 Editor, 같은 레벨 15 마을 저장, 정상 속도. `_tools/verify_bestiary_tween_cost.cs`로 3회 생성·닫기를 반복했다.

| 측정 | 변경 전 | 변경 후 |
|---|---:|---:|
| 생성된 도감 칸 | 503 | 503 |
| 미사용 저작 Tween | 2,012 | 0 |
| 열린 동안 활성 Tween | 약 2,123 | 104~111 |
| 닫기 후 활성 Tween | 81 | 81 |
| 동기 생성 시간 | 422~440ms | 418~442ms |
| 첫 UI 프레임까지 | 801~843ms | 689~729ms |
| 해당 Editor 프레임 GC 할당 최고값 | 54.8~59.1MB | 52.8~57.0MB |

GC 값은 `ProfilerRecorder`의 전체 Editor 프레임 값이며 도감만의 할당량이 아니다. `GetAllocatedBytesForCurrentThread()`는 이 환경에서 0을 반환하므로 근거로 사용하지 않는다. 시간은 3회 범위이며 실기기 성능을 의미하지 않는다.

발견/미발견 클릭 차단, 클릭 Punch, 별 1~3단계 색·회전·숨김, 동행 분홍 프레임, 무관한 Tween 보존 검사를 통과했다. 시작 용량은 7,812/625, 검사 구간 오류/경고는 0건이다. 처음 추가한 별 검사에서 Unity `Color.yellow`를 순수 FFFF00으로 잘못 가정한 검증 코드 오류는 기대 색을 명시한 뒤 재실행했다.

컴파일 후 오류 콘솔 0건을 확인하고 Play에서 실행했다. 읽기 전용 코드 리뷰에서 생산 변경 결함은 발견되지 않았고, 검증 도구에 발견·미발견·동행 전제를 명시했다.

## 남은 비용

503칸을 매번 동기 생성하는 구조와 큰 프레임 할당은 남아 있다. 이번 변경만으로 도감 지연이나 모바일 성능 문제가 해결됐다고 판단하지 않는다. 다음 작업은 화면에 필요한 목록만 생성하면서 전체 탐색·스크롤·상태 갱신을 보존하는 것이다.
