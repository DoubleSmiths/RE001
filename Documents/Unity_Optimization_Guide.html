Optimization Guide

유니티 최적화 — 측정하고, 줄이고, 검증한다

사용자 필기 + 일반 Unity 최적화 지식 + 이 프로젝트(RE001)에 실제 적용한 작업 로그를 한 곳에 모은 학습/참조 문서. 적용은 Unity Editor API로 안전하게 수행했고, 위험·보류 항목은 이유와 함께 표시했다.

APPLIED LOG

Fixed Timestep: 필기의 0.333(3Hz)은 물리가 끊겨 보일 위험 → 0.04 절충(이 게임은 물리 의존 적음).

Managed Stripping High 보류: Visual Scripting + Newtonsoft + 리플렉션 사용 → 타입 누락 위험. link.xml 작성 후 상향 가능. 현재 Low.

Always Included Shaders / Strip PostFX / DSP Buffer / AudioClip / Addressables 세부: 잘못 빼면 핑크 머티리얼·에셋 단위라 수동 검토(아래 해당 장).

01빌드 / 플레이어 설정

Managed Stripping Level code↓ build↓

안 쓰는 IL 제거(Disabled→Minimal→Low→Medium→High). 빌드·메모리↓.

  • 주의: 리플렉션·직렬화·Visual Scripting이 동적 참조하는 타입은 못 잡아 런타임 누락 → link.xml로 방어.
  • 이 프로젝트: VS+리플렉션 → Low 적용.

Strip Engine Code / Optimize Mesh Data / Texture Mipmap Stripping

  • 엔진 미사용 모듈·메시 미사용 채널·미사용 밉맵 제거 → 빌드·메모리↓. 모두 적용.
  • 주의(Optimize Mesh Data): 런타임 셰이더 스왑으로 날아간 채널이 필요해지면 문제. 2D 스프라이트 위주면 안전.

Graphics API (Android Auto off)

Auto를 켜면 Vulkan·GLES3 변형을 모두 빌드 → 빌드·셰이더 변형↑. 끄고 원하는 API만. 이 프로젝트: GLES3(2D 모바일 호환). 고사양 타깃이면 Vulkan 추가.

GPU Skinning / Graphics Jobs / Stack Trace

  • GPU Skinning: 스키닝을 GPU로(GPU 여유). on
  • Graphics Jobs(실험적): 렌더 명령 멀티스레드. on — 빌드 후 검증.
  • Stack Trace Log/Warning → None: 스택 추적은 리플렉션 비용. Error는 유지.

02물리 (Physics / Physics2D)

Auto Sync Transforms → off

Transform 변경마다 즉시 동기화하던 것을 FixedUpdate에 몰아 처리 → 동기화 비용↓. 적용

주의

같은 프레임에 이동 직후 Raycast로 결과를 즉시 읽으면 한 프레임 어긋날 수 있음(레이캐스트 의존 코드 점검).

Reuse Collision Callbacks → on

콜리전 콜백 객체를 매번 새로 만들지 않고 현재 프레임용 재사용 → GC↓. 콜백 객체를 다음 프레임에 저장해 쓰면 안 됨. 적용

Fixed Timestep

물리/FixedUpdate 빈도. 기본 0.02(50Hz). 높이면 CPU↓, 너무 높이면 반응이 밀려 보임. → 0.04(25Hz) 적용.

03그래픽스 / 셰이더

Always Included Shaders / Strip Post Processing Variants

수동 검토 — 위험

안 쓰는 셰이더/후처리 변형 제거는 빌드↓지만, 런타임 동적 셰이더를 빼면 핑크 머티리얼. Frame Debugger로 사용 셰이더 확인 후 제거.

Shader Variant Loading Settings

한 번에 로드할 청크 크기/개수 제한 → 메모리 스파이크↓. 필기 권장 chunk size 4 / count 2(필요 변형은 스왑, 비용 작음).

Sprite Atlas / Draw Call Batching 2D 1순위

스프라이트를 아틀라스로 묶어 머티리얼/텍스처를 통일하면 드로우콜 배칭. 2D 성능의 핵심. 이 프로젝트는 몬스터/UI 스프라이트가 시트별로 흩어져 있어 아틀라스 정리 시 큰 개선 여지(권장 후속).

04오디오

DSP Buffer Size

크면 CPU↓·지연↑ / 작으면 CPU↑·지연↓. 리듬게임=Best Latency, 보통=Best Performance.

AudioClip Import

  • Load Type — Decompress On Load(짧은 효과음, CPU↓/메모리↑) · Compressed In Memory(메모리↓/CPU↑) · Streaming(긴 BGM, 메모리 최소).
  • Compression Format — PCM(무압축·음질↑·메모리↑) / Vorbis·ADPCM(압축).
  • 이 프로젝트: SoundManager가 현재 사운드 비활성(PlayOneShot 주석) → 오디오 도입 시 적용.

05Addressables

  • Enable Json Catalog 해제 — 바이너리 카탈로그(역직렬화 빠름).
  • Internal Asset Naming Mode → Dynamic/FileName — 주소에서 경로 제거, 카탈로그↓.
  • Max Concurrent Web Requests = 16(저사양 8).
  • Include GUIDs in Catalog 해제 · 그룹별 Asset Bundle CRC Disabled — CPU↓.
  • Shaders 전용 그룹 — 셰이더 중복 로드 방지(다른 그룹이 쓰는 셰이더를 명시).
이 프로젝트

데이터/스프라이트/UI/VFX 그룹 존재. 위 설정은 에디터에서 수동 적용 권장(API 일부 네임스페이스 이슈).

06패키지 / 빌트인 모듈 정리

안 쓰는 빌트인 모듈(Cloth·XR·VR·Vehicles 등, Packages/manifest.json의 com.unity.modules.*) 제거 → 빌드·도메인 리로드 부담↓.

이 프로젝트는 2D 방치형 → cloth/xr/vr/vehicles 미사용, 제거 안전(권장). ⚠️ 제거 전 참조 확인.

07에셋 점검

ParticleSystem → Culling Mode = Pause

화면 밖 파티클이 실시간 계산을 멈추고 다시 보일 때 이어 재생 → CPU↓. VFX 프리팹 일괄 적용 가능(에디터 배치).

Texture

모바일 압축(ASTC), Max Size 적정화, 미사용 Read/Write Enabled off, UI Mipmap off.

08런타임 코드 최적화

Object Pooling

빈출 생성/삭제(총알/몬스터/데미지폰트)는 풀링. PoolManager 보유 → 신규 빈출 오브젝트도 풀 경유.

GameObject.Find / FindObjectOfType 캐싱 핫스팟

둘 다 씬 전체 순회(O(n)). 매 프레임/빈번 호출 금지.

  • 이 프로젝트: UI_Village1BtnGroup이 Find("Player") 반복, 일부 팝업이 FindObjectOfType<UI_*> 사용 → 캐싱 또는 Managers/이벤트 경유 권장.
  • @Skill/@Monster 등 루트 Find는 1회성이라 무방.

GC / 할당 줄이기 · Update 최소화

  • Update의 new/LINQ/문자열 보간/박싱 제거, WaitForSeconds 캐싱.
  • 빈 Update() 제거, 상태 변할 때만 이벤트 구동으로 갱신.

09에디터 리로드 / 컴파일

현재 EnterPlayModeOptions=3(Domain+Scene Reload 비활성) → 플레이 진입은 이미 최적. 느린 건 Ctrl+R 시 재컴파일 + 강제 도메인 리로드.

asmdef 분할 — 이 프로젝트는 차단됨

게임 코드 전체가 단일 Assembly-CSharp → 한 파일만 고쳐도 전부 재컴파일. 그러나 Managers ↔ UI 순환참조(UIManager가 22개 UI_ 타입 / UI_Base·UI_Popup이 Managers 참조)로 asmdef 분할 불가. 분할하려면 순환참조부터 끊는 리팩터(인터페이스/이벤트)가 선행.

  • 도메인 리로드 비용: VS·Addressables·InputSystem 초기화. VS는 코드가 의존해 제거 불가.
  • 이미 수행: 런타임 파일의 미사용 Editor/Test using 제거(위생 + asmdef 전제).
  • 권장: Preferences → Asset Pipeline → Directory Monitoring on. 근본책은 순환참조 해소 → asmdef 분할(중대형 리팩터).

10프로파일링 도구

  • Profiler(CPU/GPU/Memory/Rendering) — 병목 먼저 측정. "측정 없는 최적화 금지".
  • Frame Debugger — 드로우콜 단계, 배칭 깨지는 지점.
  • Memory Profiler(패키지) — 누수/상주 에셋.
  • RenderDoc(외부·Windows) — 가장 비싼 셰이더/드로우콜 분석 → 그 셰이더 최적화가 고효율.
우선순위 요약

1) Profiler로 병목 측정 · 2) 2D는 드로우콜(아틀라스/배칭) · 3) GC 할당 제거 · 4) 빌드 설정(대부분 적용 완료) · 5) 에디터 리로드는 순환참조 해소→asmdef가 근본책.
