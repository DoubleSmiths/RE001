## 실측으로 확인된 사실

### ① 스킬 아이콘이 하나로 통일됨 → **데이터는 정상, UI 경로 문제**
- `SkillDic` 65종 / **고유 IconLabel 65종** — 데이터상 전부 다르다
- `UI_SkillBookSkill.cs:87`은 `IconLabel`이 있을 때만 스프라이트를 갈아끼운다
- → 화면에서 하나로 보인다면 **아이콘 로드 실패 시 프리팹 기본 이미지가 남는 것**.
  런타임 로드는 65/65 성공을 확인했으므로, 스킬북 리스트가 아이콘을 안 물리거나
  다른 UI(상세정보창 등)에서 기본 이미지를 쓰는 경로가 있다. **UI별 재확인 필요**

### ② 팝업 크기 비정상 → **재현 성공, 원인은 렌더모드가 아님**
- 장비 팝업: `Canvas = ScreenSpaceCamera`, localScale 0.05
- 캐릭터 팝업: `Canvas = ScreenSpaceOverlay`, localScale 6.00
- **프리팹 저작 스케일은 전 팝업 1.0으로 정상** — 런타임에 캔버스가 결정한다
- 스크린샷: 장비 팝업이 화면 상단 일부만 차지하고 **아래쪽이 전투 HUD에 가려짐**
- ⚠️ Overlay로 바꿔보니 **팝업이 아예 사라짐**. `UIManager.SetCanvas` 주석
  ("Overlay로 강제하면 레이아웃이 깨짐")이 옳다. → **렌더모드는 원인이 아니다**
- 프리팹 조사: 루트 RectTransform의 앵커가 제각각이다. stretch(0,0)-(1,1)인 것과
  고정 앵커 + 픽셀 크기(예: 인벤 14x14, 기술책 23x20)인 것이 섞여 있다
- ❌ **시도했다가 실패한 접근**: `UI_Popup.Init()`에서 루트를 stretch로 강제 → **size가 (0,0)이 됐다.**
  팝업 루트에는 **Canvas가 붙어 있어** Canvas가 RectTransform 크기를 직접 제어한다.
  앵커를 stretch로 주면 부모(@UI_Root) 기준이 되는데 그 부모는 크기가 없다.
  → **팝업 루트의 RectTransform은 코드로 건드리면 안 된다.** (롤백함)
- 남은 방향: 루트가 아니라 **팝업 내부 콘텐츠 컨테이너**를 화면에 맞추거나,
  `CanvasScaler`의 매칭 설정(match width/height)을 세로 화면에 맞게 조정하는 쪽

### ⑥ 여정으로 던전 입장 시 몬스터 미출몰 → **부분 재현**
- 여정 팝업의 실제 경로(`TravelToNode(21120)`)로 진입 → **몬스터 2체 스폰됨**
- 다만 그중 1체가 구 슬라임 스프라이트(`Slime_Move_9`) = **fallback 2001**이 뜬 것
- **코드 순서 버그 확인**: `UI_TravelPopup.TravelToNode`가
  ```
  gameScene.EnterAreaWithFade(areaType);      // 전투 진입이 먼저
  Managers.Game.CurrentTravelAreaId = nodeId; // 지역 ID는 그 다음
  ```
  전투 루프가 서식지를 조회하는 시점에 **아직 이전 지역 ID**다.
  `PickFieldMonsterId`가 fallback(2001)로 떨어져 엉뚱한 몬스터가 나온다. → **수정 대상**

### ③ 마을이 1개 → 사실
- `TravelNodeDic`: 마을 **1** / 중분류 **3** / 전투노드 **30**
- 요구: 마을당 중분류 5개 이상, 중분류당 소분류 5개 이상 → 현재 미달

### ⑩ 몬스터와 드롭 재료 불일치 → **사실, 원인 명확**
- 503종이 **드롭 아이템 2종(10001, 10002)만** 번갈아 사용 중
- 아이템 자체가 **8종뿐** — 몬스터별 고유 재료가 존재하지 않는다
- 원인: 몬스터 대량 생성 시 `DropItemId = id % 2` 로 기계적 배분한 것(내 작업)

### ⚠️ 여정 몬스터 미출몰 — **근본 원인 발견 (미해결)**

여정 UI 경로로 던전(21010) 진입 시 몬스터는 **정상 스폰된다**(`Mon_BreezingWindForest_1`).
문제는 위치다.

    플레이어 y = 2.31
    몬스터   y = 0.01   ← 지면보다 약 2.3 아래 = **화면 밖**

즉 "몬스터가 나오지 않는다"의 실체는 **스폰은 되는데 화면 밖(지면 아래)에 있는 것**이다.
CreatureData의 `SpawnY`는 503종 전부 2.3으로 정상이고, `MonsterController`는 위치를 바꾸지 않는다.

시도한 수정(`ObjectManager.SpawnMonster`에서 y<=0이면 data.SpawnY로 보정)은 **효과가 없었다**
→ 스폰이 이 경로를 타지 않거나, 이후 다른 코드가 y를 덮어쓴다.

**다음 세션 착수점**
1. `UI_BattleBtnGroup.CoBattleLoop`의 `spawnPos` 계산이 실제로 실행되는지 로그로 확인
   (`player.transform.position.x + 12f, spawnY, 0f` — spawnY가 2.3이어야 함)
2. 스폰 직후 y를 덮어쓰는 코드 탐색 (물리 컴포넌트/Rigidbody2D 중력, 부모 스케일 등)
3. `@Monster` 루트의 transform이 y를 상쇄하는지 확인

### ✅ 여정 몬스터 미출몰 — **근본 원인 확정**

몬스터는 정상 스폰되지만 부모(@Monster) **원점(0,0)** 에 붙어 화면 밖에 있었다.

    플레이어 y=2.31 / 몬스터 localPos=(0,0,0)

원인: 생성한 애니메이션 클립이 **`m_LocalPosition` 커브**를 갖고 있었다.
Unity 애니메이션은 해당 프로퍼티를 **절대값으로 매 프레임 덮어쓴다.**
Idle/Run/Attack/OnHit/Die 5종 모두 위치 커브가 있어, `SpawnMonster`가 어떤 좌표를 줘도
재생 즉시 (0,0)으로 끌려갔다. `SpawnY` 데이터도, 스폰 코드 수정도 소용없던 이유.

**수정 완료**: `MonsterAnimGenerator`에서 위치 커브 5곳 제거.
움직임은 스케일(스쿼시)·회전·색상으로만 표현한다.

**남은 절차**: `Tools/Generate Monster Animations` 재실행으로 503종 교체.
