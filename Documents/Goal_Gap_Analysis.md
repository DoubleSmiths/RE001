### 추가 발견 (코드 레벨)
1. **`PlayerStatusData`가 사실상 죽은 데이터** — `MakeDict()`가 `DataId`(99999999)로 키를 잡는데
   `PlayerController.RefreshStats`는 `PlayerStatusDic[레벨]`로 조회 → 항상 실패.
   실제 스탯은 fallback 공식(`MaxHp=100+20×(lv-1)`, `Atk=15+3×(lv-1)`)이 담당.
   *(코드 주석도 이미 이 사실을 인지하고 있음 — PlayerController.cs:503)*
2. **성장 곡선 불일치** — 스탯은 **선형**인데 요구경험치는 **등비**.
   후반으로 갈수록 "레벨업해도 안 강해지는데 경험치만 폭증"하는 구조 → 난이도 붕괴 원인.
   300레벨 대응 시 스탯 테이블도 밴드형 성장으로 재설계 필요.
3. **`Equipment.json`은 0행** — `ItemData.xlsx`의 Equipment 시트가 비어 있음.
   실제 장비는 `EquipmentData.json`(별도 시트) 1행뿐. 두 경로가 공존하니 하나로 정리 필요.

`Tools/ParseAllLocal` 재생성 시 현재 JSON과 달라지는 항목:

| 파일 | 현재 JSON | xlsx 재생성 결과 | 판단 |
|---|---|---|---|

### 아이콘/에셋 생성 규칙 (실측으로 확정)
AetherForge API는 공식 문서와 다르다: **form-encoded**만 받고(JSON은 422), 응답은 `job_id`이며
`GET /public/v1/job/{id}` 폴링이 필요하고, urllib 기본 UA는 403(브라우저 UA 필요),
결과물은 1024² 불투명 회색 배경이라 배경 제거·크롭·NEAREST 축소가 필수다. → `_tools/aether_icons.py`

등록 시 이 프로젝트의 두 관례를 반드시 지킬 것 (어기면 런타임에서 조용히 null):
1. 어드레서블 라벨 **`PreLoad`** — `ResourceManager.Load`는 캐시만 조회한다
2. 주소 끝 **`.sprite`** — 없으면 `LoadAllAsync`가 Texture2D로 적재해 `as Sprite`가 null

## 5. 작업 규칙 (이 목표 한정)

- **엑셀이 단일 원천.** 데이터는 `Assets/@Resources/Data/Excel/*.xlsx`를 고치고 `Tools/ParseAllLocal`로 반영.

- 커밋은 기능 단위로 원자적으로. 무관한 워킹트리 수정은 건드리지 않는다.
