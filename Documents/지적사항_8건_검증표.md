## 2·5. 플레이어·몬스터가 공중에 뜨고 미니몬은 땅에 박힘

원인이 두 겹이었다.

1. **위치를 애니메이션 클립이 소유**하고 있었다. `Idle`/`Move`/`Escape`에만 `m_LocalPosition`
   커브가 있고 `Run`/`Attack`엔 없다 → 마을(Idle)에선 클립이 y를 잡아주지만 전투(Run)에선
   아무도 안 잡아 씬에 저작된 옛 y(2.31)가 그대로 남았다.
2. **pivot이 "셀 바닥"이라 발바닥이 아니었다.** 아트마다 셀 아래 투명 여백이 제각각이다 —
   플레이어 10px, 레거시 슬라임 48px, 생성 몬스터 21~25px. 같은 y에 세워도 누구는 뜨고
   누구는 파묻힌다.

**수정** `02745837` — pivot을 **보이는 발밑**으로 옮겨 여백을 흡수(`_tools/fix_ground_pivot.py`, 72개 파일).
이제 `transform.y`가 곧 발 높이라 `Define.GROUND_Y` **하나로** 전부 정렬된다.
몬스터별 `CreatureData.SpawnY` 의존과 `MONSTER_SPAWN_Y_FALLBACK`은 폐기.
동행 미니몬은 X만 플레이어를 따르고 Y는 항상 지면.

> 떨림 방지: 여백은 시트 전체의 **최소값(공통 바닥)** 으로 계산한다. 셀마다 따로 잡으면
> 프레임마다 pivot이 달라져 위아래로 떤다. 프레임 간 높이차는 의도된 움직임이다.
>
> 함정: `spriteMode 1`(Single)인데 meta에 옛 슬라이스 rect가 남은 파일들이 있어
> 그 rect 기준으로 계산하면 pivot이 엉뚱해진다(그래서 처음엔 몬스터가 계속 떠 있었다).

**검증** 플레이어 y=**2.330** / 몬스터 y=**2.330** / 미니몬 y=**2.330** (= `GROUND_Y` 2.33)
전 구간 검증에서 503마리 전부 접지 오차 0.05 이내.
재현: 신규게임 → `Test/Integration/전 구간 플레이스루 검증`

## 3. 몬스터가 공격도 이동도 안 함

**공격** — 타격 판정을 넣는 `AttackTrigger()` 호출이 **주석 처리**돼 있었다.
`//AttackTrigger();   // "Animation Event 키프레임에서 부를 것"`
그런데 클립에 그 이벤트가 끝내 안 붙어서, 몬스터는 Attack 상태로 들어가고 자세도 취하지만
**데미지가 한 번도 발생하지 않았다.**

**이동** — `ScrollLeft`가 다가오는 내내 State를 Idle로 고정하고 있었다. 사유는 주석에 그대로
남아 있었다 — "Slime Animator에 Run 없음". 아트의 한계를 상태 기계에 박아 넣은 것이다.

**수정** `dcdde863` — 이벤트에 의존하지 않고 `CoAttack` 코루틴이 타격 시점(0.25s)에 직접 호출.
클립에 이벤트가 붙어 있어도 `_attackHitDone` 가드로 한 공격에 한 번만 맞는다.
이동은 `Moving`으로 전환(Run이 없는 레거시 애니메이터는 CrossFade가 무시돼 예전과 동일).

**애니메이션 자산** `f2a92327` `1e1b9511` — aether AI로 **아키타입 30종 × Idle/Move/Attack/Die 4프레임**
아틀라스를 받아 클립 5종(Idle/Run/Attack/Die/OnHit) + 컨트롤러 생성. 생성 51건 실패 0.
상태 이름은 `CreatureController`가 CrossFade로 부르는 이름과 정확히 같아야 한다 —
하나라도 다르면 그 동작만 조용히 죽는다.

**검증**
- 애니 상태: `Idle=O Run=O Attack=O OnHit=O Die=O`
- 몬스터 공격 20회 → **명중 17 / 빗나감 3 / 총딜 202**
- 전용 애니메이터 보유 몬스터 **503/503**, 클립 5종 이상 503/503
- 처치 시 `State=Dead` 전환, Die 클립 0.46s < 파괴 0.5s (`f8438f7d`)

## 4. 장비 아이콘 불일치 + 대장간 무동작

**아이콘** — `WIcon`에 `EquipIcon` Animator가 붙어 있어 클립이 sprite를 **매 프레임 덮어쓴다**.
`UI_ForgePopup`은 이미 애니메이터를 끄고 있었는데 `UI_EquipDetailPopup`만 안 껐다.

**대장간** — 클릭 경로 자체는 멀쩡했다(장비창→상세→대장간→강화→결과 전부 동작).
막힌 건 **조건**이었다. `CanEnhance`는 `Gold >= 비용`을 요구하는데 갓 시작한 플레이어는
골드 0이고 +0 강화 비용이 120이다 → 항상 false. 그런데 화면엔 "강화불가"만 떠서
대장간이 통째로 고장 난 것처럼 보였다.

**수정** `82851848` — 애니메이터 정지 적용, 막힌 **이유**를 버튼에 표시
("골드 120 필요" / "주문서 없음" / "내구도 0" / "최대 강화", 복구는 "내구도 가득" / "재료 부족").
강화 결과 패널이 비어 보이던 것도 함께 — 값은 들어가 있었고 **색이 안 보이는 값**이었다
(능력치 쪽 alpha 0 / 잠재력 쪽 검은 배경 위 검은 글자). 겹쳐 찍히던 텍스트 4곳도 정리.

**목록 재구축** `e0fd9a4a` — 목록이 프리팹 저작 칸 수를 상한으로 삼아 **투구를 10개 가져도
1칸만** 보였다(무기만 4칸). 보유 수만큼 복제하고 ScrollRect content를 함께 키운다.
T1/T2/T3 탭은 **코드가 아예 없어** 눌러도 무반응이던 걸 등급 대역 필터로 구현.

> 함정: content가 stretch 앵커 + pivot 0.5라 높이만 늘리면 위아래로 함께 커져
> 윗변이 마스크 밖으로 올라가고 첫 행이 잘린다. 보이던 2칸이 1행이 아니라 2행이었다.

**검증**
- 아이콘: 장비창 `Equip30001` == 상세 `Equip30001` (**일치=True**)
- 대장간 팝업 열림 → 강화 팝업 → **강화 +0→+1** → 연출 팝업 생성
- 목록: 투구 T1 4칸 / T2 4칸 / T3 2칸 (보유 수와 일치)

## 6. 사냥 재료가 인벤토리에 안 들어감

실제로는 들어가 있었다. **가방 UI가 못 본 것**이다.
`UI_InventoryPopup`: `DataId > 10000 && DataId < ITEM_ID_MIN + 1000` → **10001~10999만** 통과.
몬스터 재료는 11001~11030이라 통째로 걸러졌고, 귀중품(20000+) 칸에도 안 걸려 어디에도 안 보였다.

**수정** `4ecb20aa` — 일반 아이템 = `ITEM_ID_MIN`(10000) 이상 ~ 귀중품(20000) 미만으로 정정.

**검증** 처치 시 슬라임 젤리(11001) **999 → 1000**. 전 구간 검증에서 **503마리 전부 드롭 확인**.
가방 화면에 거미줄/독버섯/늑대이빨/슬라임젤리 표시 확인.

## 7. 몬스터 이름과 이미지 불일치 (슬라임인데 늑대)

이름과 아이콘을 **서로 무관한 인덱스**로 뽑고 있었다.
- `gen_monsters`: 이름 = `bases[k % 10]`, 아이콘 = `ANIMS[(did + k) % n]`
- `gen_world`: 거기에 더해 IconLabel을 `Mon_{지역}_{did % 10}`으로 다시 덮어씀

드롭 재료도 같은 인덱스를 쓰므로 함께 어긋났다(2001 슬라임 → forest spider 그림 + 거미줄 드롭).

**수정** `4ecb20aa` — **이름을 기준으로** 재정렬(`_tools/fix_monster_archetype.py`, 503종).
한글 이름에서 심도 수식어(어린/성난/심연의…)를 떼면 base가 나오고, 그 base는 아키타입 30종과
이미 1:1이다. 거기서 IconLabel / DropItemId / AnimController를 전부 유도한다.
고블린(2003)은 전용 아트가 있어 아키타입에 끼우지 않는다.

> 나중에 전 구간 검증이 후속 버그를 하나 더 잡았다 — "이미 맞음" 판정이 아이콘·드롭만 비교해서
> 그림은 맞는데 애니메이터만 낡은 17행을 건너뛰고 있었다 (`314b0803`).

**검증** 2001: 이름 **슬라임** / 아이콘 `Mon_BreezingWindForest_0`(slime blob) /
애니 `Mon_BreezingWindForest_0` / 드롭 `11001`(슬라임 젤리) — 넷이 같은 아키타입.
전 구간 검증에서 503종 전부 이름↔그림 정합 통과.

## 9. 던전이 산들바람 숲 하나만, 그 안에 3개뿐

데이터는 정상이었다(25지역 × 5던전 = 125). UI가 `IsTravelNodeUnlocked`로
**잠긴 노드를 목록에서 제거**하고 있었고, 레벨 게이트가 12레벨 간격이라
레벨 1에서는 지역 1개 + 던전 1~3개만 남았다.

**수정** `02745837` — 잠긴 노드도 표시하고 회색 + 해금 조건 문구를 붙인 뒤 클릭만 막는다.
`GameManager.GetTravelLockReason`을 판정의 단일 출처로 두고 `IsTravelNodeUnlocked`는 그걸 감싼다.

**검증** 신규게임(Lv1) 기준 **여정 지역 25개 표시 / 산들바람 숲 던전 5개 표시**
(잠긴 곳은 "레벨 13 이상이어야 갈 수 있습니다" 등 조건 문구 표기)
