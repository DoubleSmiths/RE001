1. 미구현 · 스텁 기능

데이터 랭크업 미구현 기능 공백

랭크업은 현재 연출(이펙트+토스트)만 있고 GameData.AdventurerRank는 아무도 쓰지 않아 항상 0(BLANK). 필드·세이브·HUD 표시가 전부 준비돼 있어, QuestUnlockType.RANK_SET 추가 + 퀘스트 시트 한 행 + ProcessUnlocks case 하나 + HUD 갱신 이벤트면 완성. (기대값: 퀘4 완료 시 5)

물약 보유 수량 스텁 인벤토리 미연동

UI_PotionPopup의 수량이 count = 5 하드코딩이라 팝업을 껐다 켜면 5개로 리셋. 물약을 실제 아이템/인벤토리와 연동해 소모·저장되도록 해야 함.

UI_EquipmentPopup 부분 구현 장비 시스템

장비 팝업은 내비게이션만 구현된 상태(코드에 명시). 장착/강화(대장간 T1→T3)/내구도 등 기획서 5-3 장비 시스템 본체 작업 필요. 연계: DataManager에서 ForgeRecipe/CraftRecipe 시트 로드가 주석 처리돼 있어 GameManager.ForgeEquipment가 사실상 죽은 경로.

UI_FieldTypeButton 미구현 여정 팝업

SetInfo()가 빈 몸체 + TODO. 여정 팝업의 필드 타입 필터 버튼 기능 구현 필요. TOWN 카테고리도 현재 마을 1개(아스달)뿐 — 마을 추가 시 BTN_TOWN 유도 키/노드 확장.

전투 버튼 그룹 느낌표 미구현 Quest Notify

UI_BattleBtnGroup.RefreshNotify()가 빈 함수(프리팹에 VFX 오브젝트 없음). 전투 씬 버튼에도 퀘스트 유도 느낌표가 필요하면 프리팹 오브젝트 추가 + 바인딩 연결.

전직 시스템 미구현 장기

PlayerName이 "여행자" 고정. UI_SkillDetailPopup 주석에도 의도적 미구현으로 명시 — 기획 확정 후 착수.

TimeManager 미등록 방치형 코어

Managers.cs에서 주석 처리 상태. 오프라인 보상·스태미나(CLAUDE.md 설계의 방치형 핵심 루프)가 아직 없음.

2. 데이터 · 파이프라인 리스크

시트 ↔ JSON 동기화 밀린 항목 파서 실행 필요

게임은 JSON만 읽으므로, 로컬에서 수정한 JSON은 구글시트에 반영하지 않으면 다음 파서 실행 때 되돌아감:

수정된 JSON내용시트에 할 일
QuestUnlockDataUNLOCK_INVENTORY_BUTTON: 퀘2 → 퀘1 (통행증 획득 즉시 가방 해금)동일 이동
QuestData퀘2에 팔로우 지정 (젤리 퐁 0/2 즉시 표시)FollowItemID=10001, 이름, Count=2
ComboDataColorHex 신 팔레트 반영 완료로컬 ComboData.xlsx가 구버전 — 구글시트 파서만 사용하거나 로컬 xlsx 동기화
CreatureData(진행 중)Name을 Localization TextKey로 전환 작업 중Name 컬럼에 TextKey 기입 규칙 확정

DataTransformer 취약점 구조적

컬럼 인덱스(row[i++]) 기반 파싱이라 시트 컬럼 순서 변경이 파괴적(이번 "슬라임 이름 1" 계열 사고의 배경). Extra 8종 시트는 enum을 문자열로 저장(StringEnumConverter)해 enum 이름 변경도 호환성 파괴. 장기적으로 헤더명 기반 파싱 전환 권장.

세이브 스팸 성능/수명

GameManager의 여러 property setter가 변경 즉시 SaveGame()(전체 직렬화+파일 쓰기) 호출. 전투 중 빈번한 변경 시 IO 부담 — 더티 플래그 + 주기 저장으로 배칭 권장.

3. 코드 · 에셋 정리

이름/잔재 정리 혼동 방지

① CameraController.cs 안의 실제 클래스는 FixedResolution (파일명 불일치) ② UI_TtitleScene 파일명 오타 ③ UI/Legecy/UI_BattleBtnGroup_Legecy.prefab 미사용 레거시 ④ 폴더명과 달리 UI_SubItem 베이스 클래스는 없음(대부분 UI_Base 직상속) — 정리하거나 컨벤션 문서화.

UI 파티클 규칙 준수 재발 방지

월드 ParticleSystem은 SSC 캔버스 위에 직접 렌더되지 않음 — UI 위 이펙트는 반드시 UIFx.PlayParticle()(UIParticle 래퍼) 경유. 씬에 저작된 Quest_Done_Effect류도 실제 게임 뷰에서 보이는지 QA 필요.

5. QA · 자동화 제안

연출 자동 녹화 확대 QA 효율

UnlockAnimRecorder(메뉴 1클릭 → 플레이 진입 → 연출 트리거 → MP4 저장) 패턴이 검증됨. 대화 오프닝/랭크업/퀘스트 팔로우 등 다른 연출에도 같은 방식의 녹화 메뉴를 추가하면 기획 수정안 대비 검증이 빨라짐.

바인딩 검증 자동화 회귀 방지
